# MacMusic 1.1: the release's checks

| | |
|---|---|
| Version | 1.1 |
| Date | 2026-10-13 |
| Tested by | the project owner |

**Released without the full manual checklist,** by the owner's choice
(2026-10-13): MacMusic is for the owner's own use, and the owner accepts
the risk. What was checked:

- **The automatic tests,** passed by the release build
  (`tools/make-release.sh` runs both): `tests/run-host.sh` and
  `tests/run-smoke.sh`.
- **Mini vMac,** by the owner, after each step of Parts A-D (each commit
  was approved after that check): the cut-off prompt, the cache and
  "Loading the library…", printing's dialogs and layout (no printer),
  the File menu, the window in front, importing one song after another.
- **The real Plus** (4 MB, System B-6.0.7, MultiFinder, BlueSCSI):
  - the 1.1 test build `2d1694f` (2026-10-12): start-up 32 s, which led
    to Part D;
  - the timing builds (2026-10-12): the grouping fix (N11-32) and the
    optimised build (N11-30) bring a 316-song start to about 13 s, and
    an import to about 12 s.

**Not yet checked:** printing on paper (the ImageWriter and other
printers), the 1 MB Plus, and the rest of the manual checklist's
section 10 on the Plus. Anything found goes in `docs/issues-found.md`
for 1.1.1.

## The owner's checks on the real Plus, after the release (2026-11-11)

- **Start-up:** the library opens quickly.
- **Importing several songs** (Import Another): used, and worked well.
  A fuller report will follow the next time it's used.
- **MacMusic in front at start-up** (N11-28): yes, it comes to the
  front.
- **The 1 MB Plus:** not to be checked on the real Plus (it would mean
  opening the Plus to take SIMMs out). 1.1's Part 0 measured the memory
  of a 1 MB configuration instead (`docs/outstanding-issues.md`,
  "Accepted limitations").
- **Printing on paper:** still to come.
- **Found:** the music sounds really odd while a disk is read (the
  issues log, 2026-11-11).
